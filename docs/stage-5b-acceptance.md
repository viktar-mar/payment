## Native clock and remaining gates

The existing [Stage 4 business-clock harness](local-development.md#stage-4-subscription-rollout-and-acceptance) is a Fake acceptance facility. It does not prove ownership of a Stripe TestClock. Current Billing Customer creation does not supply an owned `test_clock` context, and the native ownership/time-domain seam is **not implemented**. Merely injecting the Stage 4 clock would mix billing time with UTC grant/quote expiry, provider leases/retry windows and callback queue scheduling; it cannot establish safe Billing acceptance. Native quote/cancellation proof and historical immutable fingerprints also require explicit treatment before those scenarios can be claimed.

Remaining acceptance work is:

- Resolve the consumed-browser failure-to-successor-retry capability gap without treating provider status, time, lost ACK or a consumed grant as permission.
- Complete Task 12 Billing-specific PostgreSQL/Cucumber and owner/browser contracts, plus the complete default Fake browser and existing 5A regression checkpoint. Authored or compiled tests count only after execution.
- Implement and review exact owned native-clock provenance and the billing/UTC/monotonic time separation before native trial/renewal/grace or other clock-driven scenarios. There is currently no supported Billing runner command to publish here.
- Finish independent review, migration/source/privacy checks and exact-publication hosted verification for the combined source.
- Under separate explicit runtime authority, execute fresh owned Billing cases from the accepted design: initial success/decline/manual 3DS; trial/method isolation; renewal/failure/grace/recovery; changes/cancel/withdraw/resume; Portal policy/return; webhook reorder/missed recovery. Preserve exact provider-to-local cash and signed callback evidence, first-failure/UNKNOWN stop rules and the explicit financial budget for test-clock advances.

All actual Stripe Billing provider scenarios in this matrix remain **NOT_RUN**. Stage 5A's historical accepted evidence and unresolved operational records are preserved separately.
