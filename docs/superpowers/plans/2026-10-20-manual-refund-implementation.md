# Manual Sandbox Refund Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить отдельный offline-tested режим возврата EUR7 → EUR13 исходного оплаченного EUR20, с одной будущей ротацией callback-ключа только его тестового Site; без запуска Sandbox сейчас.

**Architecture:** Отдельные state/options/report contracts, restoration capability сохранённой topology, узкий platform refund session и тонкий controller entry. Старые bootstrap prepare/start, full smoke и unpaid manual-payment flow не используются для принятия старого run. Возвраты выполняются существующим backend; CLI — только binding/listener/read proof, не финансовые writes.

**Tech Stack:** Node24 ESM, native node:test/strict assert, существующие pinned Docker/Stripe CLI adapters; Java/backend/API/DB и browser SDK не меняются.

**Spec:** [Ограниченный возврат уже оплаченных EUR20 в Sandbox](../specs/2026-10-20-manual-refund-design.md). Объём и one-Site rotation подтверждены в чате; этот подробный план ожидает проверки пользователя до реализации. Sandbox по-прежнему запрещён.

## Global Constraints

- Первый вариант намеренно привязан только к исходному успешному manual-payment run `031b5ae7-6603-4339-b1b3-77231291ff34`, source `f0620e40004162d2b3eededa60512f50a492f4cc`.
- Привязка остаётся `acct_1UPiMpELswAd8tpR`, API `2026-09-30.endive`, Stripe CLI `1.52.0`, test mode.
- Новое списание, Checkout или PaymentIntent не создаются. Ввод карты и браузерная страница не нужны.
- Второй возврат разрешён только после независимого подтверждения первого в Stripe, локальном журнале и подписанном callback.
- Ни note, ни PII нет; API только существующий защищённый /api/v1/admin/payments/{paymentId}/refunds, reason_code REQUESTED_BY_CUSTOMER, currency EUR, суммы700/1300.
- Произвольные Site/Payment/provider IDs, суммы, endpoint URLs и credential paths не принимаются от оператора.
- Исходные runtime/provisioning/private files никогда не переписываются. Не выводятся Config.Env, raw inspect или конфигурация Compose.
- Реальные ключи и run files не читаются даже для «диагностики» тестов. Сейчас запрещены Docker/Compose runtime, Stripe CLI/OAuth/listener, provider/Admin/финансовые запросы.
- Одна новая active authority ≤30min от начала refund entry; cleanup только до исходной новой deadline+2min. Каждое HTTP/provider read ≤10s, proof phase ≤30probes/45s.
- Read-only разбор PENDING — отдельное решение оператора, не автоматическое завершение второй операции. Удаление/пересоздание ресурсов и повтор неизвестного dispatch запрещены.
- Каждая задача: meaningful RED→GREEN, целевые и связанные regressions, отдельное независимое review требований и качества.

## Review Focus

1. Истёкшие CLI credentials или signing-secret mismatch: никаких auto-login, secret overwrite или financial writes (Task2).
2. Смешение original/new source, подмена retained inode/topology, неожиданный третий Refund или другой Admin actor: stop до следующего изменения (Tasks1–3).
3. Rotation/configure потеряли ответ или конфигурация поменялась: одна разрешённая rotation могла произойти, но ни повторов, ни возвратов (Task3).
4. Late command/HTTP settlement после abort, crash между POST и durable receipt, новая runId для обхода неизвестного исхода: PENDING; ни €13, ни второй refund POST (Tasks1,3,4).
5. Сумма верна, но journal/outbox/receiver/provider Event связаны не теми IDs: не принимать денежное/callback/webhook доказательство (Tasks2,3).

## Files and interfaces

Все новые файлы — `infrastructure/stripe-manual-refund*`. Purpose-specific единицы: `-options`, `-schema`, `-state`, `-runtime`, `-session`, `stripe-manual-refund.mjs`; соответствующие `.d.mts` и `.test.mjs`. Отдельный `.mjs` у entrypoint обязателен; остальные единицы не имеют direct-entry I/O. Не создавать новое frontend приложение или backend API.

Общие типы в `stripe-manual-refund-options.d.mts`:

- `RefundOptions`: readonly `{env, runId, expectedSource, daemon}`; original run/source и ports не являются входом и выводятся только из fixed target/validated original manifest.
- `Limits`: readonly `{deadline:number, signal?:AbortSignal}`.
- `OriginalRefundTarget`: readonly safe IDs `originalRunId, originalSource, project, containers, images, network, volumes, ports, endpoints, account, site, price, paymentId, operationId, intentId, callbackVersion:1`; фиксированные `amountMinor:2000, currency:'EUR', source:'CATALOG'`. Private credentials не входят в этот тип.
- `RefundLeg`: readonly `{amountMinor:700|1300,key:string,phase:'READY'|'DISPATCHING'|'ACKNOWLEDGED'|'CONFIRMED',refundId:string|null,providerReference:string|null}`.
- `RefundProof`: readonly `{refundId,providerReference,providerEventId,amountMinor:700|1300,totalMinor:700|2000,providerVerified:true,webhookVerified:true,journalVerified:true,callbackVerified:true}`; это внутренние safe references, не stdout.
