# One-use original-debt recovery confirmation

## Intent and boundary

Continue Stage 5B with an actual, explicitly constructed financial producer for the already authenticated original failed renewal. It confirms the existing PaymentIntent with the independently confirmed saved method. It neither creates a replacement payment nor uses invoice.pay. Implementation and verification are offline; execution against a provider is outside this change.

Baseline ec2e3ad has successful full CI (5689 backend cases, one existing skip) and dedicated renewal CI (379 cases). The original null-pay recovery proof, completed SETUP and original RESERVED RECOVER remain immutable. A response to the write supplies provider evidence only. The independent recovered observer/FactService retains settlement, cash, journal and callback authority.

## Decisions made by the implementer

- New dedicated provider kind `OWNED_RECOVERY_INTENT_CONFIRM`, resource = original RECOVER, key = its providerOperationKey + `:CONFIRM`. This deliberately has no ordinary reservation/claim/recovery path.
- The strictly guarded provider row itself is the immutable ownership relation, joined through the unique original method recovery. A separate immutable first-claim commit receipt and append-only ACK table store the original claimant/deadline and normalized successful reply evidence. No extra descriptive ownership table is needed.
- Atomic insert RESERVED0, immutable first-claim receipt and first claim DISPATCHING1 in one transaction. The claim receipt pins its creating xid8 using pg_current_xact_id(); both terminal transitions require a different transaction. Reject same-transaction terminalization even after SET CONSTRAINTS ALL IMMEDIATE. Any existing row, including RESERVED0, refuses adoption. Only ACK2 or UNKNOWN2 may follow; no reset/reacquisition/retry. Existing 23-hour retry_before remains a schema field, never permission for another attempt.
- Confirm parameters are exactly saved payment_method, off_session=true, error_on_requires_action=true. Accept only exact original PI/customer/method, sandbox, succeeded, original currency/amount, received==amount, capturable==0, automatic capture, card-only methods, no last error/next action, and a bounded latest_charge reference. This does not assert that the charge differs from the earlier declined charge or prove allocation settlement. Do not change the existing preflight graph to manufacture that assertion.
- An unsupported/SCA/processing/error/timeout response fails closed; no browser action or replacement attempt is invented. Native compatibility with pinned API and invoice allocation is NOT_RUN until a future authorized test.

## Durable authority and transactions

Use `OwnedRecoveryConfirm` model, default-denied `OwnedRecoveryConfirmStore`, explicit `OwnedRecoveryConfirmService`, `JdbcOwnedRecoveryConfirmStore`, additive V37, and unregistered `StripeBillingOwnedFailedRenewalRecoveryConfirmAdapter`.

Service entry accepts an expected RecoveryPreparationContext, original SubscriptionCommandContext and (after claim) the exact claim. That context is descriptive, not a permit. Each claim, inspection and ACK freshly reauthenticates through the real original recovery-preparation validator. Extract a package-private transaction seam in OwnedFailedRenewalMethodService, preserving public inspect as a fresh single requiresNew read. The seam authenticates immutable original enrollment/reservation before caller-derived locks, locks actual scoped operations in canonical order, then invokes the dedicated receipt lock by authenticated account/RECOVER/kind, then final original browser/session validation, mutation and post-mutation raw exclusive expiry/authority validation before commit. It must not nest a REQUIRES_NEW store call or move the original public read into an ambient transaction.

Original SETUP stays SUCCEEDED2, RECOVER stays RESERVED0; Completion, Recovery, bill/version, invoice/allocation/PI, sample, revision, failure+1 sequence, owner/account credentials and original management enrollment must match. A prior RECOVERED read or publication refuses financial admission. Locks never derive from a supplied claim ID before authenticating its canonical resource. A failure after blocking work rolls back speculative claim/ACK. Actual provider I/O occurs outside every transaction.

Dedicated store methods join the caller transaction. The service alone starts fresh transactions. UNKNOWN cleanup authenticates immutable stored relation and exact invocation claim, uses canonical operation-before-provider locking and may only consume its own still-DISPATCHING1 claim. It grants no financial authority even after lease/session expiry. A failed cleanup preserves consumed evidence; stop only the original owned admission, never acquire a new claim. An already committed ACK is returned without a postcommit budget rejection.

## SQL and ordinary-path isolation

V37 extends the kind check and creates immutable `stripe_billing_failed_recovery_confirm_claims` plus append-only `stripe_billing_failed_recovery_confirm_acks`. The claim relation pins original reservation/provider row/claimant/claimed_at/lease deadline and invocation UUID/entered_at/deadline_at (exactly entered+30 seconds), with a trigger-authenticated creating xid8. Claim insert is allowed only for the original RESERVED0 row; deferred checks require that transaction to finish DISPATCHING1. Require an independently committed claim for both terminal transitions and live invocation UTC deadline for positive dispatch/ACK checks. It is a commit-fence receipt, not a second descriptive ownership table. Its kind-scoped provider trigger inspects OLD and NEW, rejects deletion/kind conversion/identity changes/scheduler bookkeeping/reset/version skips, and admits only pristine0 -> first1 -> ACK2/UNKNOWN2. ACK and reply receipt commit together, with a deferred constraint checking the OLD claimant/deadline. Original reference is failure.paymentIntent. Validate owner pins, exact canonical fingerprint, completed original browser lineage, live management session/origin/scopes/site/customer/account, original debt and post-lock DB UTC for positive transitions. Deferred insert/state checking must prevent a committed orphan RESERVED row.

Fingerprint uses StripeRequestFingerprint/owned_method_stripe_hash over original account/external account/credential/provider/mode, action `OWNED_RECOVERY_CONFIRM_V1`, original RECOVER id/key/fingerprint, reservation id, failure bill id/version/invoice/allocation/PI/revision/sequence, binding/customer, completed SETUP/METHOD IDs/versions, method and fixed parameter literals. Compare a hand-derived Java/SQL golden value in hosted composition.

Preserve V27_4's null pay_step/pay_kind, V34's INVOICE_PAY exclusion and V35/V36 lineage. Explicitly extend original association policy so this kind is accepted only for the exact dedicated original relation; enum omission is not an admission mechanism. Do not require a new writer receipt for old observer-only fixture histories.

Typed Java acquires upstream locks before provider rows. Direct SQL cannot invert blocking locks: use ordered NOWAIT authority locks where necessary, separate post-lock clock_timestamp checks and reject contention. No timeout-only assertion counts as observed lock/expiry refusal.

Generic JdbcProviderOperationStore reserve/claim/ACK/UNKNOWN/manual binding/lockRecovery and other mutation entry points deny this kind. PendingProviderRecoveryPersistenceAdapter excludes it before selection/row lock for both polling and explicit-ID acquisition, and finish checks persisted kind rather than trusting the caller's claim. Scheduler fields are frozen by SQL. Other ordinary kinds retain their behavior.

## Bounded SDK producer

Public adapter confirm(Reservation,Completion,Recovery,SubscriptionCommandContext) returns redacted ConfirmationAck. It obtains the independent current remote preflight itself; caller cannot inject PreparedRecovery. Use a final OwnedRecoveryConfirm.InvocationBudget constructed at adapter entry with Clock and LongSupplier: it captures a fresh invocation UUID, actual/injected starts and raw UTC entry/deadline and exposes remainingNanos(ProviderOperation) with fixed 30-second bounds. Pass this SAME instance through claim/inspectClaim/acknowledge and the reader internal overload. Check it after final blocking mutation/revalidation inside the caller transaction; service raw UTC must also be before its original deadline. A delayed transaction commit/return after the last valid precommit checkpoint does not invalidate a committed ACK; there is no literal commit-time or return-latency guarantee. One immutable budget begins before authentication and includes that reader, credentials/client, all stores and confirm: 30 seconds in actual and injected monotonic time and raw UTC, reject rollback. Synchronous caller-side storage has no forced cancellation guarantee, but cannot authorize later work/result after returning past budget.

Exactly one logical SDK POST with original PI and fixed parameters, API 2026-09-30.endive, zero SDK/application retries, deterministic idempotency key, at most two seconds connect/read/complete-call including scheduling, original raw session expiry and exact live 60-second claim checked immediately before SDK entry. Cancellation bounds local wait, not remote effects or physical wire attempts. No network inside SQL transactions. Prewrite failed remote graph is not rerun after success: only unchanged local original authority and exact claim/reply precede ACK. Independent later recovered observation validates changed remote settlement.

Errors have fixed code OWNED_RECOVERY_CONFIRM_UNAVAILABLE, status409, safe fixed message, no cause/suppressed/raw SDK payload. Descriptions redact identifiers/secrets. No route, Spring registration, native runner, dependency or browser permission change.
