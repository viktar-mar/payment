## Intent, scope and approaches

Follow one original subscription, failed renewal bill and committed G−1 → G → G+1 clock lineage through genuine original browser SETUP, METHOD, one dedicated confirmation of the original failed PaymentIntent, independent CASH observation/publication, then actual get/access returning PAID at the saved G+1. Never infer settlement from browser success, ACK, a saved clock, supplied ACTIVE state or another fixture.

Selected controller approach: optional, explicitly requested successor on the existing immutable UNIQUE(admission_id) METHOD reservation, referencing the actual AFTER READY. Reuse existing producers and reader in place. Automatic inference from AFTER would silently change old APIs; a parallel handoff/preparation framework adds redundant authority and orphan states; a selector-only change cannot overcome the deliberate V39 branch exclusions or remote clock expectation. Those alternatives are rejected. A narrow claim-provenance/terminal receipt is necessary for original-owner cleanup because old SETUP/METHOD ACKs erase their lease owner.

Preserve old migrations V30–V40 byte-for-byte, old APIs/constructors/READY2 writer sample, old untagged METHOD and legacy recovery, uniqueness, original receipts, security UTC and default Fake. No production bean, route, launcher, runtime export, ordinary invoice.pay, generic retry, new dependency or financial authorization. Native failed-renewal/grace/recovery remains NOT_RUN, full5B NOT_ACCEPTED.
