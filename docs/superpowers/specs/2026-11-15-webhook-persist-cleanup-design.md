## Design

Only OWNED_FAILED_RENEWAL_GRACE_RECOVERY changes persistence policy. Validate the same exact three-assignment grammar, test-key restrictions, private regular-file identity and bounded unchanged-file proof. A previous webhook must be empty or a well-formed whsec value, but is not this invocation's verifier. Use the freshly validated listener secret only in this fresh run's exclusive, durable final.env. No shared user-file replacement, temporary replacement or user-env.lock acquisition/read/unlink. All other modes retain current empty/equal-only policy and checked shared-writer behavior. No write retry after uncertainty.

Track a sticky failed-mode-only persistence diagnostic from a finite local-checkpoint allowlist. Ignore raw dependency errors; never include keys, values, paths, bodies, pairing or counts. Durable private store then original acknowledgement remain prerequisites for START. A failed store/ACK keeps original DISPATCHING/ACK uncertainty and pending fence; a safe diagnostic is not readiness.

Allow failed-mode stop to prove the exact PREPARED pre-start persistence-failure shape: retained live owner descriptor, all seven recorded IDs, no retired backend/live state, one final PERSIST_WEBHOOK/backend-key-persistence intent and only prior acknowledged actions. The final memory intent may remain DISPATCHING or, only at PERSIST_ACK, retain its actual ACKNOWLEDGED projection after uncertain ACK publication or failed input close. Every failed persistence is excluded from generic all-ACK cleanup. Fresh infrastructure/project/image/ownership proof plus five never-started Created services and two successful nonrunning exited helpers are mandatory. No START, stop command, financial call, resource adoption/removal, global writer action or invented/reversed ACK. Publish no cleanup ledger: preserve exact runtime.json bytes even when the dispatch is absent durably or ACK rename preceded a failed directory sync. Preserve memory projections, original intents and sticky pending state. Consume the owner descriptor once, including ambiguous close; subsequent stop refuses. Identity drift, unknown creation and unrelated pending action still refuse cleanup. This proves only this invocation's stopped resources, not old shared-lock release or rollback of unknown writes.

The failed owner captures the finite persistence checkpoint on LISTENER refusal and exposes a closed terminal formatter/parser. The dedicated test attaches a trusted formatted terminal annotation only after owner close. Before accepting it, the reporter requires exactly one onTestBegin matching the exact target case/file/project/expected status, the same TestCase and TestResult objects, zero retry and no reserved terminal annotation in either begin array. A declared reserved annotation refuses delivery even when Playwright later copies it into both end arrays on setup failure. Missing, mismatched or repeated begin proof refuses delivery. With a clean begin, the reporter emits at most one validated fixed diagnostic for the exact target case/project. It continues to suppress raw stdout/stderr/errors/attachments, including after CLI handoff. Report primary stage and actual cleanup proof separately. Failure or cleanup proof never becomes successful acceptance; the existing success predicate is unchanged.
